# v2 작업표시줄 산책 모드 — 베타 (v0.17.41)

## 배경

- v1 은 드래그로 옮기는 플로팅 펫. v2 는 **작업표시줄 윗선을 따라 출근개미가 걸어다니고**, 뒤로
  집·회사·업비트/비트겟 타워가 서 있는 "작업표시줄 마을" 표시 모드.
- 그림·도구 파이프라인은 `notes/V2_SPRITE_PIPELINE_NOTES.md` 참조.
- 아직 베타라 **해제 파일이 있는 사용자만** 켤 수 있다 → 우클릭 메뉴 > 표시 스타일 > "작업표시줄 산책 (베타)".
  (해제 방식은 아래 "해제 파일" 섹션)

## 추가/수정

### main.js
1. `walkerWin` — 작업영역 하단에 **모니터 폭 × 340px** 투명 띠(`WALK_STRIP_H`). 바닥 = 작업표시줄 윗선.
   모니터는 오버레이가 있던 모니터(숨겨져도 위치 유지) → 없으면 주 모니터.
   `focusable:false`(포커스 안 뺏음), 기본 `setIgnoreMouseEvents(true, {forward:true})`.
2. `applyDisplayStyle()` / `setDisplayStyle()` — 산책 모드면 산책 창 생성 + **오버레이는 숨김만**
   (오버레이의 시세 WS·트레이 아이콘·무드는 계속 동작). 다른 스타일로 가면 산책 창 destroy + 오버레이 복귀.
   메뉴의 표시 스타일 항목과 `set-setting(displayStyle)` 모두 여기로 모인다.
3. 오버레이 `backgroundThrottling:false` — 숨긴 상태에서도 WS 재연결 타이머·시세 중계가 늦어지지 않게.
4. IPC
   - `walk-interactive`: 산책 창만. 개미 위일 때만 마우스 받기.
   - `walk-toggle-panel`: 클릭한 개미 사각형(화면 좌표)을 `walkAnchor` 로 저장 후 패널 토글.
   - `price`·`pet-test` 중계 대상에 산책 창 추가. `pet-context-menu` 는 보낸 창 기준으로 popup.
   - `set-setting` 가드: 해제 관련 키 직접 설정 금지, 미해제 상태의 `displayStyle=walk` 무시.
5. `anchorPanel()` — 산책 모드면 개미 바로 위 가운데. `togglePanel()` 은 산책 모드에서 저장된 panelPos 무시.
6. `ensureOverlayOnTop()`/`recoverOverlay()` — 오버레이·산책 창 중 **보이는 창** 모두 대상.
   `display-metrics-changed` 에서 `layoutWalker()` 로 새 작업영역에 다시 맞춤.
7. 중복 실행(second-instance) 시 산책 모드면 숨긴 오버레이 대신 산책 창을 앞으로.
8. "펫 보이기/숨기기" 는 산책 모드에서 산책 창 대상.

### 렌더러 (walker.html)
- `renderer/walk/walker-app.js` — 오케스트레이터. BTC 시세는 main 중계(`onPrice`), 무드는

## 불변사항 / 주의

- **v1 오버레이 코드·CSS·무대 기준선은 변경 없음.** 산책 모드는 오버레이를 숨길 뿐 파괴하지 않는다
  (시세 WS 소유자이자 트레이 아이콘 갱신 담당).
- 산책 띠 높이(`WALK_STRIP_H`)는 개미·마을 축소·전광판 배율로 계산한 값. 크기 설정을 추가하면 같이 조정할 것
  (아래 후속 섹션에서 340 → 230).
- 투명 띠는 클릭 통과지만 **건물이 선 자리는 화면을 가린다**. 건물 숨기기/크기 설정은 미구현.
- 검증 범위: 산책 창 렌더러는 가짜 btcpet API 하네스로 헤드리스 렌더링 확인(오류 없음, 건물·개미·전광판 표시),
  업비트 웹소켓 파싱은 Node 로 실연결 확인. **Electron 실제 실행(창 위치·클릭 통과·패널 위치·메뉴)은 미검증.**
- dev 실행(`npm start`)은 설치된 BTC Pet 과 **같은 userData(settings.json)와 단일 인스턴스 락**을 쓴다
  → 설치본을 종료한 뒤 실행해야 하고, 해제·표시 스타일 설정이 설치본에도 남는다.

## 후속: 마을 축소 + 왼쪽 모음 배치 (같은 0.17.41, 미배포)

### 원인
- 사용자 실행 결과(2560px 모니터): 거래소 타워 288px 가 작업 중 화면을 너무 가림.
- 화면 폭 비율 배치(10·33·64·86%) 때문에 넓은 모니터에서 **가리는 곳이 네 군데로 흩어짐**.

### 수정 (walk-scene.js, main.js)
1. `TOWN_SCALE = 0.65` — 건물 높이 = heightUnits × 72 × 0.65 (거래소 약 187px). 개미는 72px 유지.
2. 전광판은 건물만큼 줄이면 글씨가 안 읽혀 `BOARD_SCALE = 1.5 × 0.85 / 0.65` 로 역보정
   → 축소 전 150% 전광판의 85% 크기 유지. 테두리 두께도 전광판 배율에 비례.
3. 배치: 비율 배치 제거 → **왼쪽 구석부터 집·회사·업비트·비트겟을 붙여 모음**
   (여백 12px, 간격 14px, 전광판이 타워보다 넓으면 전광판 폭을 차지 폭으로 계산해 겹침 방지).
   오른쪽 구석은 윈도우 알림 팝업 자리라 제외, 양 끝 분리(출근길)는 가리는 곳이 두 군데라 보류.
4. `geometry()` 로 건물 크기·전광판 사각형 계산을 한곳에 모음(draw·layout·requiredHeight 공용).
5. `WALK_STRIP_H` 340 → **230** (계산상 필요 높이 약 205px).

### 불변사항 / 주의

## 해제 파일 (같은 0.17.41, 미배포)

- 산책 모드는 개인별 해제 파일(`.btcpet`)로 켠다. 발급·키 관리는 저장소 밖에서 하며,
  **그 경로·절차·한계를 저장소 파일(코드 주석·노트·CLAUDE.md)에 적지 않는다.**
- 적용 경로: 펫·패널 창에 **끌어다 놓기**(preload.js 가 공통 처리, 드롭 시 페이지 이동 기본 동작도 막음),
  **더블클릭**(package.json `build.fileAssociations` → 앱 실행 인자 / `second-instance` argv).
- 성공 시 "OO님, 산책 모드가 열렸어요 [지금 켜기/나중에]" 다이얼로그 + 패널 하단 `🐜 산책 모드 · 이름님`.
- `get-settings` 는 해제 원문 대신 `walkUnlocked`·`walkLicenseName` 만 넘긴다. 해제 키 직접 설정 금지.
- .gitignore — `*.btcpet`.
- 주의: 더블클릭은 파일 연결이 등록된 **설치본**에서만 동작(dev 는 드롭으로 테스트). 클릭 통과를 켠 펫 창에는
  드롭이 안 될 수 있음 → 패널에 드롭.

## 해제 파일 형식 v2 · 사용 기간 (0.17.42, 미배포)

- 원인: 공개키 하나·영구 파일만 지원 → 여러 서명 키와 기간제 파일이 필요.
- 수정 (main.js):
  - `WALK_LICENSE_PUBLIC_KEYS` = `{ kid: PEM }`. v1 파일은 `p1` 키로 검증(기존 파일 그대로 유효).
  - v2 필드: `kid`, `tg`(빈 문자열 가능), `exp`(마지막 사용 가능일 `YYYY-MM-DD`, 빈 문자열 = 기간 없음).
    서명 문자열 = `["btcpet-unlock","v2",kid,feature,id,name,tg,issuedAt,exp].join("\n")` (`LICENSE_FIELDS`).
  - `exp` 는 로컬 날짜로 비교, 그날까지 사용 가능. 기간이 끝난 파일을 넣으면 "사용 기간이 끝난 해제 파일" 안내.
  - `isWalkUnlocked()` 캐시는 날짜가 바뀌면 다시 검증. `recheckWalkLicense()` 10분 주기 —
    산책 중 기간이 끝나면 산책 창을 닫고 기본 표시로(설정 `displayStyle` 은 그대로, 새 파일을 넣으면 복귀).
  - 저장은 `pickLicense()` 로 버전별 필드만. `get-settings` 에 `walkLicenseExp` 추가 → 패널 `🐜 산책 모드 · 이름님 · 날짜까지`.
- 불변: v1 파일 형식·검증 결과 변화 없음. 해제 원문은 렌더러로 넘기지 않음.
- 검증(Node): v2 영구/기간 내 통과, 만료·exp/tg/kid 조작·v1→v2 위장 거부, 기존 v1 파일 통과.

## 산책을 못 쓰게 됐을 때 산책 전 스타일로 복귀 (0.17.43, 미배포)

- 원인: 기간이 끝나도 저장값 `displayStyle` 은 `walk` 로 남는다(새 파일을 넣으면 복귀하려고).
  그래서 우클릭 메뉴 표시 스타일에 체크가 하나도 없었고, 오버레이는 재시작하면 산책 전 스타일과 상관없이 기본값 펫으로 떴다.
- 수정:
  - main.js `rememberPrevStyle()`: 산책으로 바꿀 때(`setDisplayStyle`·`set-setting`) 직전 스타일을 `walkPrevStyle`(pet/pill)에 저장.
  - `baseStyle()`: 저장값이 walk 면 `walkPrevStyle`, 아니면 저장값 (둘 다 pill 이 아니면 pet).
  - 메뉴 체크: 산책 중이면 산책, 아니면 `baseStyle()` 에 체크.
  - `recheckWalkLicense()`: 산책 창을 닫은 뒤 오버레이에 `displayStyle = baseStyle()` 을 방송(저장값은 walk 그대로).
  - overlay-app.js: 시작 시 저장값이 walk 면 `walkPrevStyle` 로 스타일 결정.
- 불변: 저장값 walk 유지 → 새 해제 파일을 넣으면 산책으로 복귀. `walkPrevStyle` 이 없는 기존 산책 사용자는 펫.
- 검증(Node): pet/pill→산책→만료, 산책 중 재선택, 산책→펫→산책, 기존 사용자 6가지 경우 메뉴·오버레이 스타일 일치.

## 우클릭 메뉴를 표시 모드별로 (0.17.44, 미배포)

- 원인: 메뉴가 모드와 상관없이 전부 보여서, 산책 모드에 펫 캐릭터·펫 크기 같은 쓸모없는 항목이 보이고
  펫 모드에도(해제된 사용자) 마을 위치·산책 범위가 보였다.
- 수정 (main.js `buildMenu()`): `mode = isWalkMode() ? "walk" : baseStyle()` 로 항목을 고른다.
  | 모드 | 보이는 전용 항목 |

  | walk | 마을 설정, 산책 캐릭터(2명 이상), 마을 위치, 산책 범위, 산책할 모니터·넘어다니기(2대 이상), 마을을 다른 창 위에 표시 |

### 원인

### 수정
1. **창 너비** — 렌더러가 `requiredSpan()`(산책 범위 ∪ 마을·전광판 ∪ 현재 개미 위치, 32px 단위)을 `walk-span` 으로
   보내면 main 이 그 구간만큼 창을 자르고 `walk-viewport {fullWidth, offset}` 회신. 렌더러는 항상 작업영역 전체 폭
   좌표로 계산하고 `offset` 만큼 밀어서 그림(마우스도 +offset). 전체 폭을 받기 전엔 요청하지 않음(창 폭을 전체 폭으로
   오인해 계속 줄어드는 루프 방지). 범위가 "화면 전체"면 전체 폭.
2. **겹침 단계** — 산책 창 `setAlwaysOnTop(true, "floating")`: 일반 창보다 위, 작업표시줄 쪽 창보다 아래
   (Electron: floating~status 는 Windows 작업표시줄 아래, pop-up-menu 이상은 위). v1 오버레이는 기존 screen-saver 유지.
   메뉴 "마을을 다른 창 위에 표시"(settings.walkOnTop, 기본 켬) 끄면 일반 창처럼 다른 창 뒤로 감.
   20초 최상위 재선언도 walkOnTop 일 때만, floating 단계로.
3. **트레이** — blur 로 숨긴 시각을 기록해 300ms 안의 트레이 click 은 무시(닫기 동작). 산책 모드 패널은
   `tray.getBounds()` 기준 **트레이 아이콘 바로 위**(못 얻으면 마을 반대편 구석).

## 후속: 창 크기 변경 순간 번쩍임 (같은 0.17.41, 미배포)

### 원인
- 창을 옮기거나 크기를 바꾸면(setBounds) 윈도우가 **마지막으로 그려진 프레임을 새 위치에 한 번 보여 준 뒤** 새 프레임이
  올라온다. offset 을 매 프레임 다시 계산해도 이 한 프레임은 렌더러에서 막을 수 없음 → 마을을 놓은 직후 한 번 번쩍.

### 수정 (walker-app.js)
- 창 구간 변경을 바로 보내지 않고 `requestResize()` → 장면 페이드: **out 120ms → clear(빈 프레임 1장) → 창 변경 →
  settle 150ms → in 200ms**. 창을 바꾸는 시점에 화면에 올라가 있는 프레임이 빈 화면이라 옮겨 보일 게 없다.
- 첫 창 배치는 보여 준 적이 없으므로 페이드 없이 바로 맞추고, 첫 배치 전(viewport 수신 전)에는 그리지 않음.
- walk-scene.js `draw({alpha})` — alpha 0 이면 지우기만, 그 외엔 캔버스 opacity 로 적용.
- 창 구간 변경은 마을 옮기기·산책 범위 변경·옮기기 모드 진입/종료 때만 일어나므로 평소엔 페이드가 보이지 않음.

### 검증
- 헤드리스 가상 시간 모드는 requestAnimationFrame 이 거의 돌지 않아 타이밍 측정 불가(마지막 그리기 3.4초 전) → 부적합.
- 대신 페이드 코드를 그대로 추출해 Node 에서 16ms 프레임으로 시뮬레이션: 1.0→0 으로 사라진 뒤, **직전에 그린 프레임의
  투명도가 0 인 상태에서만** 창 변경 호출, 이후 0.2초에 걸쳐 1.0 복귀. (clear 단계 추가 전엔 직전 프레임 9% 잔상 가능성 있었음)
- 실제 윈도우에서 번쩍임이 사라졌는지는 Electron 실행으로 확인 필요.

  되걸 때마다 깜빡이며 무한히 싸운다. 전체화면 앱이 어느 모니터에 있는지는 알 수 없다(윈도우가 전역으로 내림).
